Descripción General del Proyecto

En esta práctica se configuró una red de área local (LAN) de forma física y real, conectando varias computadoras mediante un switch y cables de red fabricados por el propio equipo de trabajo. A diferencia del proyecto de Packet Tracer (simulado), esta actividad se realizó con hardware real dentro del salón de clases.

El objetivo fue lograr que todas las computadoras del grupo pudieran comunicarse entre sí, compartir archivos y recursos dentro de una misma red, asignando direcciones IP estáticas manualmente y configurando un nombre de Grupo de Trabajo común para todas las máquinas.

Pasos de Configuración Realizados

Paso 1 — Conexión Física

Se conectaron todas las laptops y PCs al switch mediante los cables de red RJ45 fabricados previamente. Cada integrante del grupo enchufó su cable en un puerto disponible del switch. Se verificó visualmente que los LEDs del switch indicaran conexión activa en cada puerto.

Paso 2 — Asignación de IP Estática

En cada computadora se configuró manualmente una dirección IP estática dentro del mismo rango de red para que todos los equipos pudieran reconocerse. La configuración aplicada fue:

ParámetroValor configurado
Dirección IP192.168.X.X (diferente para cada equipo, mismo rango)
Longitud del prefijo / Máscara24 / 255.255.255.0
Puerta de enlace192.168.1.1
DNS preferido8.8.8.8 (Google DNS)
IPv6Desactivado

En Windows la configuración se realizó desde: Panel de Control → Centro de redes → Cambiar configuración del adaptador → Propiedades del adaptador → Protocolo de Internet versión 4 (TCP/IPv4) → Manual.

En Ubuntu la configuración se realizó desde: Configuración → Red → Editar configuración de IP → Manual, ingresando los mismos parámetros.

Paso 3 — Configuración del Grupo de Trabajo

Para que las computadoras con Windows pudieran verse entre sí en la red local, se configuró el mismo nombre de Grupo de Trabajo en todos los equipos. Esto se realizó desde: Panel de Control → Sistema → Configuración avanzada del sistema → Nombre de equipo → Cambiar → Grupo de trabajo.

Todos los integrantes usaron el mismo nombre de Grupo de Trabajo, lo que permitió que los equipos se reconocieran automáticamente dentro de la red y facilitó el intercambio de archivos y recursos.

Paso 4 — Verificación con ipconfig

Desde la consola CMD de Windows (o terminal en Ubuntu) se ejecutó el comando ipconfig para verificar que la dirección IP estática había sido asignada correctamente al adaptador de red. Se revisaron los siguientes datos:

  • Dirección IPv4 asignada correctamente.
  • Máscara de subred: 255.255.255.0
  • Puerta de enlace predeterminada: 192.168.1.1
  • Estado del adaptador: conectado y activo.

Paso 5 — Prueba de Conectividad con ping

Se utilizó el comando ping seguido de la dirección IP de cada compañero para verificar que la comunicación entre equipos funcionara correctamente. Un ping exitoso confirma que los paquetes viajan desde una máquina a otra a través del switch. 

Ejemplo:
C:\Users\usuario> ping 192.168.1.2
Haciendo ping a 192.168.1.2 con 32 bytes de datos:
Respuesta desde 192.168.1.2: bytes=32 tiempo<1ms TTL=128
Respuesta desde 192.168.1.2: bytes=32 tiempo<1ms TTL=128

Estadísticas de ping para 192.168.1.2:
    Paquetes: enviados = 4, recibidos = 4, perdidos = 0 (0% perdidos)

Preguntas y Respuestas de la Práctica

1. ¿Fue necesario usar el cable cruzado para conectar las PCs al Switch? ¿Por qué crees que funcionó o no funcionó con el directo?

No fue necesario el cable cruzado. Para conectar una PC a un switch se utiliza el cable directo, ya que este nos permite conectar dispositivos de diferente tipo (PC con switch). El cable cruzado se usaría para conectar dos PCs directamente entre sí sin switch. Además, la mayoría de los switches actuales tienen tecnología Auto-MDIX que detecta automáticamente el tipo de cable y se adapta, por lo que incluso un cable cruzado podría funcionar.

2. Al cambiar la IP a estática, ¿qué pasaría si dos personas del mismo grupo ponen la misma IP (ej. 192.168.1.1)?

Se genera un conflicto de IP. Esto provoca que las computadoras tengan problemas de conexión, ya que la red no puede identificar correctamente a cada equipo con la misma dirección. Como resultado, puede fallar la comunicación entre los equipos afectados o incluso perderse el acceso completo a la red para ambas máquinas. Windows muestra una advertencia de "conflicto de dirección IP" en la barra de tareas.

3. ¿Qué ventaja tiene usar un nombre de Grupo de Trabajo igual para todos los integrantes?

Usar el mismo nombre de Grupo de Trabajo facilita que las computadoras se reconozcan automáticamente dentro de la red local. Esto permite compartir archivos, carpetas y recursos (como impresoras) de manera más rápida y sencilla, además de hacer más organizada y visible la conexión entre los equipos del grupo.

Topología Implementada

La red configurada en el salón de clases siguió una topología en estrella: todos los equipos se conectaron a un único switch central, que actúa como nodo de distribución. Ningún equipo se conectó directamente a otro, sino que todo el tráfico de datos pasó a través del switch.

  • Ventaja: Si una computadora falla, las demás siguen comunicándose sin interrupción.
  • Ventaja: Es fácil agregar o quitar equipos sin afectar al resto de la red.
  • Desventaja: Si el switch falla, toda la red deja de funcionar.

Competencias Adquiridas

  • Configuración manual de direcciones IP estáticas en Windows y Ubuntu.
  • Comprensión del funcionamiento de una red LAN física con switch.
  • Uso de herramientas de diagnóstico de red: ipconfig y ping desde consola.
  • Identificación y solución de conflictos de IP en redes locales.
  • Configuración de Grupo de Trabajo para compartir recursos en red.
  • Comprensión de la diferencia entre cable directo y cruzado y su uso correcto.
  • Aplicación práctica de la topología en estrella con hardware real.
